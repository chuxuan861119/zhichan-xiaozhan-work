# DWG 转换路线验证结果

日期：2026-09-13。试验分支：`codex/dwg-conversion-evaluation`；起点 main `a1af93a6`。

目标：对用户提供的同一 DWG 比较官方 ACadSharp → ACadSharp.Pdf 与官方 ACadSharp → DXF → ezdxf SVG；将已有本项目读取适配补丁作为单独对照。此次不实现标号、圈选、图片导出界面，不修改正式应用。

## 判定标准

检查原文件不变、转换进程结果、读取和绘制阶段告警、输出结构，以及轮廓、样条曲线、现有标号、剖面线和特殊局部放大图的可见性。生成文件、退出码为零、未知实体数为零，都不能单独证明完整还原。

## 样本与实测

私有样本只保存在本地，未提交内容、路径或图纸派生物。样本 405944 字节、AC1032；模型空间 1795 个对象：1160 Line、139 LwPolyline、162 Arc、204 Spline、34 Ellipse、33 Hatch、4 MText、59 Insert。

| 路线 | 本轮结果 | 判定 |
| --- | --- | --- |
| 官方 ACadSharp 3.7.1 → ACadSharp.Pdf 0.1.5-beta | 生成 1386319 字节、1 页 PDF，但导出告警明确跳过 59 个块引用、33 个填充、204 条样条；画面缺少大量标号、剖面线、曲线细节和底部局部图。Poppler 报告流长度、F1 字体资源及内容流语法错误 | 该固定版本组合不满足本样本底图要求 |
| 官方 ACadSharp 3.7.1 → DXF → ezdxf 1.4.4 SVG | 生成 1392512 字节 SVG；可见标号、轮廓与剖面线。DXF 审计错误/修复均为 0，绘制跳过为 0，29 次图案填充调用；但 DWG 读取阶段有 1 个未知 ACIDBLOCKREFERENCE，底部圆内为空 | 普通内容可显示；不能认定整图完整 |
| 已有适配补丁 7057e090 → DXF → 同一 SVG 脚本 | 生成 1418393 字节 SVG；同样没有 DXF 审计错误或绘制跳过。恢复 1 个特殊引用，指向含 520 个实体的实际目标块；底部圆内管束结构已在新生成画面中显示 | 值得继续验证的候选，不能当作官方库原生支持 |

官方读取约 194 ms、DXF 输出约 114 ms、PDF 输出约 564 ms；SVG 绘制分别约 0.85 / 0.87 s。均为本机单次测量，包含各脚本定义的阶段范围，不是性能基准或保证。

## 源码与诊断边界

- PDF 试验使用官方发布二进制，ACadSharp.Pdf 固定版本的依赖下限为 ACadSharp 3.3.0，本轮显式使用 3.7.1；没有测试所有版本组合或未发布 master。不能把结论扩大为“所有 PDF 转换器都不可行”。
- PDF 的异常属于该次输出的可复现结果；没有修改上游绘制器来掩盖缺失。
- SVG 阶段未跳过，不代表读取阶段没有丢失。官方原版的未知实体告警与空圆画面对应。
- 适配版仍报告 Invalid SpatialFilter；其他只读任务记录过零法向量，本轮没有把它修成猜测的裁切平面。当前全图和局部图可见，不代表其他空间裁切一定正确。
- 两组 SVG 都报告 relative point size is not supported；字体可能替代。没有取得原 CAD 同尺度完整输出进行逐像素或逐对象核验，不宣称绝对保真。
- 已有恢复器只取 `7057e090` 提交快照，未读取其工作区未提交实现作为本轮基线；适配快照单独构建成功，0 错误、48 条上游警告。

## 实际验证与交付范围

- 官方试验工具 .NET 构建：0 警告、0 错误。两条官方路径使用同一次 DWG 读取；本轮修正了试验工具对第三方输入流所有权的处理，然后重新执行并生成独立输出目录。
- PDF 实际通过 Poppler 渲染并检查全图；同时保存其错误诊断。生成的 PDF 是失败对照样本，不能用于正式附图。
- 两组 SVG 均实际渲染为 PNG，检查整图和适配版底部局部图；SVG 是可重新渲染的矢量底图，PNG 仅为检查预览。
- 仅下载公开依赖和源码；图纸在本地转换，未上传第三方。
- 最终重新读取原文件摘要，与本轮转换记录一致。已有输出目录拒绝覆盖且文件摘要未变；非 DWG 输入被拒绝且未创建输出目录。
- 两个 SVG 均通过 XML 结构检查，图形元素分别为 1968 / 2488；增加 520 与恢复块内实体数相符，但元素数量不是完整保真判据。
- 本地对比页通过隐藏 Edge 检查：3 个切换页、3 张图片解码、缩放均通过，0 页面异常、0 HTTP(S) 请求。没有激活系统窗口。PDF 页以实际渲染的失败样本 PNG 展示，SVG 页使用原矢量输出。
- 锁文件恢复和最终 .NET 构建通过，0 警告、0 错误。无生产代码改动，未运行与转换工具无关的应用全量测试，也未重启用户实例。

建议继续采用“DWG 读取适配 → SVG 底图 → 独立标号 → 圈选/框选成图”的方向，并保留 PDF 导入。当前仅一个真实样本；更多版本、字体、代理实体、布局空间、裁切行为、生产分发及正式应用交互均未验收。
