# 专利工作台发布检查清单

本清单只定义发布规则，不再保存会随界面、测试数量或安装包哈希迅速过期的结果。每次候选发布必须运行 `npm run release:evidence`，以当前 Git 提交为目录生成 `release/evidence/<commit>/report.json` 和 `report.md`。

版本分配、三端渠道、更新发布顺序和恢复规则见 [版本与发布更新方案](version-release-update-plan.md)。每次发行复制 [发布记录模板](releases/TEMPLATE.md) 为 `docs/releases/<版本>.md`，关联本清单产生的真实证据；模板不是已完成验收报告，自动生成器的人工项默认未执行。

## 判定规则

- 自动门禁全部通过，只代表当前提交通过自动验证。
- Windows、macOS、Office/WPS、打印、SmartScreen 和许可证法律复核必须保留为人工证据，不能由源码存在、测试名称或历史结果推断为通过。
- 任一数据丢失、文件损坏后崩溃、生产外连、许可证材料缺失或核心流程失败，均阻塞发布。
- 人工项未完成时，证据报告必须显示“正式发布就绪：否”，即使自动门禁全部通过。

## 自动门禁

证据生成器按当前清单依次执行：

1. 静态检查与 TypeScript 检查。
2. 全部单元测试和应用构建。
3. Electron 核心 E2E 与独立性能门禁。
4. 高危依赖漏洞审计与第三方许可证审计。

命令、退出码、耗时和当前提交号由 `scripts/release-evidence.mjs` 生成，不在本文手工抄写。

## 人工发布矩阵

以下各项必须在对应候选安装包上记录实际版本、环境、操作者、时间和结果：

| 检查项 | 最低要求 |
| --- | --- |
| Windows 10 干净账户 | 安装/卸载、启动、新建与编辑、退出重进、PATDOC、导出、异常提示 |
| Windows 11 干净账户 | 与 Windows 10 相同，并检查高 DPI 与最大化/双文档布局 |
| Mac Apple Silicon 干净账户 | 安装/卸载、Finder 应用、Dock/状态栏、正常退出/恢复、PATDOC、DOCX/PDF、CAD/流程图 |
| Mac Intel / 最低支持系统 | 同上，并核对当前打包配置声明的最低 macOS 版本及原生组件架构 |
| Mac Gatekeeper | Developer ID 签名、公证、隔离属性与首次离线/联网启动，不能用开发实例代替 |
| Mac 输入与触控板 | 中文组合输入、Command/Control/Option、系统保留键、双轴滚动、捏合、外接鼠标、窄窗口弹层 |
| Microsoft Word / WPS | 打开单书及合并 DOCX，检查文字、表格、公式、页眉页码和分页 |
| 打印 | 至少一个 PDF 虚拟打印机；正式交付前按目标环境补物理打印机 |
| SmartScreen | 记录未签名安装包的联网与离线路径，不得宣称具有发布者证书 |
| 第三方许可 | 有资质人员复核随包 notices 及上游版权信息缺口 |

## 数据安全专项

- 正常退出后再次启动，不应出现异常恢复提示。
- 强制终止后再次启动，必须显示恢复检查结果；已经确认写入的编辑可继续使用。
- 恢复报告不得显示专利名称、正文、文件路径或密钥信息。
- 数据库完整性失败时进入只读保护，不能以空库覆盖原数据。
- 备份和快照引导可以暂缓，但用户必须能随时进入数据安全设置。

## 既有候选版

`v0.1.0-rc.1` 因确认存在立即关闭时的数据丢失缺陷而作废，不得继续分发。历史标签不构成当前版本的发布证据。
