# 使用统计接收服务

本服务接收过去1至7个自然日的固定汇总，不提供用户注册、登录、反馈或公网读取接口。统计数字可能漏记、重复或被伪造，不用于计费、审计或精确人数计算。

## 本地构建与运行

需要 Node.js 24.15 或更新的兼容 24.x 运行时。项目现有依赖足够，无新增服务端依赖。

```sh
npm run build:usage-service
node out-usage-service/main.mjs serve /absolute/path/config.json
```

配置结构见 `config.example.json`，仅记录数据库路径、公开发行组、回环端口、保留月数与全局每分钟请求预算。示例是虚构部署路径，不能据此宣称正式服务已开放。运行进程采用 `umask 077`，服务目录与 SQLite/WAL/SHM 文件只授权服务账号和必要运维账号。不要把数据库、配置或快照放入公网静态目录。

入口绑定 `127.0.0.1`，由 HTTPS 反向代理仅转发 `POST /v1/usage/daily-aggregate`。其他路径返回 404；错误正文不回显载荷。内容类型须为 JSON，正文最多 2 KiB；未知字段、非法日期／版本组／计数返回 400。事务提交后返回 204；数据库失败为 503。协议3/4以每份日报独立随机凭据幂等接收，同份重放返回204但不重复累计，凭据相同而内容不同返回409，已冻结日期返回410。断网、超时、429与5xx可退避补发；其他4xx不反复重试。超过7天未运行仍可能漏记，不能当作完整日活。

全局请求预算是进程保护措施，不是安装去重或完善的防刷系统。生产入口另需配置体积、超时、来源限流和预算告警；来源信息只用于安全防护，不加入业务汇总或用户画像。

## 运营报表

独立接收服务可由主机运维通过 CLI 发布和读取。现有生产部署另接入受认证的统一后台 `https://zcxzz.cn/admin-statistics/`，支持次日暂定区间、D+8固定日报筛选与 CSV；这不是软件用户注册系统。部署与每日备份见 `services/admin-statistics/README.md`。

```sh
node out-usage-service/main.mjs publish /absolute/path/config.json 2026-10-05 releases
node out-usage-service/main.mjs report /absolute/path/config.json 2026-10-05
```

`publish` 只允许已结束上报窗口的日（协议3为D+8或更晚，旧固定视图保留原窗口）。新协议使用 `releases` 视图，分开平台、完整版本、渠道。`all` / `versions` 仅兼容旧数据，含发行维度数据的日期禁止用旧视图发布。首次发布后冻结，同一天无法切换或组合视图。`report` 只读取已发布固定快照，不开放原始汇总或重算任意维度组合。

活跃贡献不足 10 时，活跃值与整份时长分布均显示空值；此规则也用于读取旧固定快照。达到活跃贡献门槛后，时长先尝试六档，再按固定三档、两档合并；只有所有非零桶均达到 10 时才发布一个完整层级，否则不显示分布及其总数。阈值不是自然人数或 k-匿名证明。

服务启动及每日维护删除超过配置保留月数（最多 18）的业务汇总与快照，开启 SQLite 安全删除并截断 WAL；检查点被占用时报告保留维护失败，需运维排查。历史备份、磁盘快照和云副本的删除仍须部署时单独配置并验证，不能以数据库行已删除代替所有副本已删除。

## 正式开放条件

1. 用户确认运营主体、联系方式、云接收方与地域、保存期、网络安全日志、备份与访问权限。
2. 配置受控 HTTPS 域名、TLS、来源限流、资源预算；关闭正文日志、调试转储与 APM 载荷捕获。必要安全日志独立存储和限制权限，不关闭依法要求的安全日志。
3. 完成目标平台真实焦点、最小化、隐藏、锁屏、休眠、原生模态窗口和断网验收；在 `resources/usage-statistics-channel.json` 中仅填入已验收平台、公开发行组和完整告知。客户端配置随安装包构建，不接受环境变量覆盖。
4. 服务端发行组与客户端一致，汇总保留期和用户披露一致；资料或处理范围变化提高告知版本，重新取得确认。
5. 核实实际等保对象与属地要求，完成真实基础设施留存检查。

2026-10-18 客户端与生产服务已同步开放 Windows 1.1.2 preview，其他平台和旧协议白名单保持关闭；新包运行并确认完整协议、且用户未关闭统计后才采集。开发、测试、带独立用户目录的临时实例与未验收发行元组不计时、不上报。鸿蒙电源/锁屏原生桥及模拟调用已完成，仍须新 HAP 构建与设备验收。当前公开历史预览包未替换。

新协议使用严格 `{platform, version, channel}` 白名单，拒绝未发行组合和额外字段；同日升级沿用该日首次计数的发行元组。客户端旧状态升级保留关闭选择与发送水位，清除不能准确标注的新协议待发计数，要求新版告知确认。数据库新增表，不推断旧数据的平台/补丁版本/渠道。详细验证与限制见 `docs/changes/unified-statistics/cross-platform.md`。

## 协议3修复（2026-10-18）

生产入口不接受没有随机上报凭据的旧协议。去重记录只保存随机凭据摘要及固定字段的载荷摘要，与业务计数同事务；补发窗口后例行删除。诊断保存自然日、结果和计数30天，后台仅展示结果是否被观察到，不公开可反推小样本的实时接收总数。主机安全日志继续独立管理。随机凭据不是账号、设备或安装证明，不保证不同凭据来自不同真人。当前生产升级的实际结果见 `docs/changes/unified-statistics/reliability-v3.md`。
